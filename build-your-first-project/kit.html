Part 1: Claude basics

Pick a model

Click the model name next to the send button. Claude keeps your last pick.

ModelSpeed and costUse it for
HaikuFastest, cheapestLight work: fix a sentence, summarize an email, reformat a list.
SonnetBalancedEveryday, non-technical work: draft an email or recap, summarize a document, answer questions about a file. Start here.
OpusSlower, smarter, uses moreComplex, technical work and analysis: a long report, a big spreadsheet, a plan with many steps.
FableSlowest, "smartest", burns through usageOnly the toughest problems, when Opus can't get there.

See how much you've used ($) in Settings, then Usage.

Set the effort

Effort is how much Claude thinks before it answers. It's in the same menu, under Effort. Leave it on High.

  • Slow or long-winded? Drop to Medium or Low for routine work. It's faster and uses less.
  • Shallow answer to a hard problem? Try Extra high before you rewrite the prompt.
  • Avoid Max, even for technical work. It's very slow, and Claude can overthink and give you a worse answer.

Write a good prompt

  1. Set the stage: who you are, your goal, the background.
  2. Define the task: exactly what you want.
  3. Set the rules: length, tone, format, and an example if you have one.
Weak
"Write an invite email for our next AI lunch-and-learn."
Better
"I run a monthly lunch-and-learn on AI tools for about 30 coworkers, most of them new to AI. Write the invite email for next month's session on Claude Projects. Under 120 words, friendly and plain, no hype. Start with what they'll be able to do afterward, then the date and the meeting link."

When the result is off

If it'sDo this
Too genericSay who it's for, your role and your limits.
The wrong lengthGive a length: "under 120 words", "3 bullets".
The wrong formatPaste an example of what you want.
The wrong toneDescribe it plainly ("friendly, not salesy") and add an example.
Confident but wrongCheck it. Ask where it got that, or what it's unsure about.

Treat the first draft as a starting point and say exactly what to change. "Under 120 words" works better than "make it shorter".

Brain dump 5 minutes

For big or fuzzy tasks: dump everything in one chat, let Claude interview you and write the prompt, then paste that prompt into a new chat.

  1. Start a new chat with Chat selected, not Cowork. Paste the Brain dump prompt.
  2. Under "My brain dump:", write everything about a task you need to do this week. Messy is fine. Shift+Enter adds a line, and dictation works too.
  3. Answer Claude's questions. "You decide" is a fine answer.
  4. Click Copy on the prompt Claude writes. Open a new chat, paste it and send.
Brain dump prompt
I'm going to brain dump about a task I need to do. It will be messy. Don't do the task yet. First, interview me to fill the gaps:
- Ask one question at a time, then wait for my answer.
- Start each question with your best guess, so I can just confirm or correct it.
- Ask about what matters most first: my goal, who it's for, what done looks like, and anything I haven't decided yet.
- Stop when you have enough. Aim for 6 to 8 questions at most, and never ask more than 10.
- If I say "you decide", make a decision, say what you chose and why in one short line, and continue.
- If I say "write it now", stop asking and write the prompt.

Then list any assumptions you made in one line, so I can fix them. After that, write a prompt I can paste into a new chat to get the work done. Use three parts: set the stage (who I am, my goal, the background), the task, and the rules (length, tone, format). Put only the finished prompt inside one code block, so I can copy it with one click.

Context

Your messages, Claude's replies and your files all take up room in a chat's context, Claude's working memory. Back-and-forth is fine, but once a chat is mostly full, Claude gets worse at using it. AI Hero calls these the smart zone and the dumb zone.

Smart zoneDumb zone
Normal back-and-forth
Very long chat, big files
  • Setup: instructions, memory
  • Your messages
  • Claude's replies
  • Files
Compacting

When a chat gets very long, Claude summarizes the older messages and shows "organizing its thoughts". Details can get lost, and long chats use more of your allowance.

New chat

A clean start, back in the smart zone. If Claude starts forgetting what you told it, start a new chat and bring only what matters.

Turn on memory 3 minutes

With memory on, Claude remembers things like your role, your work and how you like things written, and brings them into new chats. Depending on your plan, it may be off until you turn it on.

  1. Click your name or initials (bottom left), then Settings.
  2. Open Memory.
  3. Turn on Generate memory from chats.
  4. Open Topics and delete anything wrong or out of date. To add something, tell Claude "Remember that..." in any chat.

To keep one chat out of memory, click + in a new chat's message box and switch Memory off before your first message.

Memory knows you loosely, in every chat. A Project knows one job exactly, from your instructions and your best example. Each Project also has its own memory.

Sprint 1: Create the Project

Don't click "Use a folder." It makes a local Project that only lives on your computer, and you can't share it.

  1. In the Claude desktop app, click Projects in the left sidebar. No sidebar? Click the icon at the top left.
  2. Click New Project and name it. Leave Visibility on Private and click Create project.
  3. Next to Context, click +, then Upload from device. Upload your good example, plus a template if you have one.
  4. Keep your starting point for Sprint 3.
  5. See a customer's personal details in the file? Delete them and save, or pick a different example.

PDF, Word, CSV, Excel and text files all work. If the page says "Local projects are only available on this computer", you clicked "Use a folder". Make a new Project without it.

Sprint 2: Have AI write your instructions

  1. On your Project page, select Chat in the message box. It may be set to Cowork.
  2. Paste the Project Starter. Before you send, replace [WHAT YOU MAKE] with your wording from the build menu, like "my weekly update to my manager".
  3. Answer Claude's questions one at a time. "You decide" is fine.
  4. Click Copy on the box with your instructions.
  5. Click your Project's name at the top. Click + next to Instructions, paste, and click Save instructions.

This Starter is one good way to write instructions, not the only one. Change the headings or bullets to fit your work.

Project Starter
I'm setting up this Claude Project for one thing I make over and over: [WHAT YOU MAKE].

Read the files in this Project first. Then interview me to write the Project instructions:
- Ask one question at a time, then wait for my answer.
- Start each question with your best guess, based on my files and how this kind of work is usually done, so I can just confirm or correct it.
- Ask about what matters most first: who it's for, what good looks like, and anything my files don't show.
- Ask as few questions as you can to get the full picture. Aim for 6 to 8 at most, and never ask more than 10.
- If I say "you decide", make a decision, say what you chose and why in one short line, and continue.

Then write my instructions in plain text. Use these exact headings (the words before each colon), each on its own line, with no markdown symbols:
Context: who I am, what this is for, and who reads it.
Process: the steps you follow, in order.
Tone and format: how it should sound and look, based on my examples.
Specific requirements: 3 to 5 rules, each with a short reason. Include these two word for word, each followed by a reason: "If information is missing, say so and ask. Never invent numbers or facts." and "Mark anything you inferred."
When I give you: what I'll usually give you, and what you do with it.

Put only the finished instructions inside one code block, so I can copy them with one click. Nothing else inside the block, and no other code blocks or sample drafts.

Sprint 3: Use it, check it, teach it

  1. Use it. Start a new chat in your Project with Chat selected. Paste your notes, or attach the file with +. No notes? Type 3-4 bullets about a real meeting this week. Then ask for the thing in your own words (examples below).
  2. Read it. Check the facts, names, dates and numbers against your notes.
  3. Check it. Paste the Check it prompt in the same chat. Claude checks accuracy, compares the draft with your example, and writes one sentence for your instructions.
  4. Teach it. Copy that sentence. Click your Project's name, click + next to Instructions, add the sentence at the end and click Save instructions.
  5. Try again in a new chat with the same notes, since a new chat doesn't remember the old one. Still not right? Check it once more and add a second sentence.

Check it prompt
Check your latest draft in two ways:
1. Accuracy: is every fact, name, date and number backed by what I gave you? List anything that isn't.
2. Match: compare it to the examples in this Project's files. List up to 3 differences that matter most. If it already matches well, say so. Don't look for differences that aren't there.
Then write one sentence I should add to the Project instructions to fix the most important problem you listed. Put only that sentence in a code block so I can copy it.

Don't over-check. Once or twice is enough. If you keep asking Claude to find problems, it starts inventing them and the draft gets worse.

Done early? In a new chat, give it the same notes plus "Treat [one number] as missing." Claude should flag the gap instead of making up a number.

Your name is on it: 4 checks

Claude drafts it, and you own it. Read it and verify it before you send it. It should be short, make sense and sound like you. If you couldn't defend it as your own work, it isn't ready.

  1. Read it, all of it.
  2. Understand it. If you couldn't explain it, don't send it.
  3. Validate it. Facts, names and numbers match your source. Check anything Claude marked as inferred.
  4. Make it yours. Your words and tone, no filler or jargon. You'd sign it.

Sprint 4: Use it for real

  1. Pick something you need this week that your Project makes. Start a new chat, give it the input and ask in your own words.
  2. Run the 4 checks and edit until you'd sign it.
  3. Optional: click Share (top right of the Project page) and add a teammate. They see your instructions and files, not your chats, and it appears in their Projects under Shared with you. Then paste the Teammate prompt and send them the one-liner.
    • Can view: they can see the Project and chat with it. Pick this one.
    • Can edit: they can change your instructions and files. Usually you don't want that.
Teammate prompt (optional)
Write the shortest prompt a teammate could use with this Project: one sentence, with one [blank] for what they paste in. Put only that prompt in a code block so I can copy it.
